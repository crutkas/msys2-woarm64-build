=== B5 CORRECTION (coordinator, 2026-09-03) — pwd -W IS NOT A RUNTIME DEPENDENCY ===
My earlier framing ("MinGit assembly must run INSIDE MSYS2 ... same class as the sh gate") was
WRONG in an important way and is corrected here so it does not propagate as a false dependency
on the runtime track:

make-file-list.sh / mingit/release.sh RUN ON THE BUILD HOST and only COPY and LIST files. The
PACKAGES they assemble are ARM64; the SCRIPT itself need not be ARM64 and need not run under the
ARM64 msys-2.0.dll. An EXISTING x86-64 MSYS2 satisfies `pwd -W` (and cygpath, /usr/bin, ldd, the
absolute /clangarm64 mount) TODAY. So:

  MinGit-arm64 CAN BE ASSEMBLED RIGHT NOW on an x86-64 MSYS2 host, WITHOUT waiting on the ARM64
  msys-2.0.dll runtime. Assembling an ARM64 artefact from an x86-64 host is a PACKAGING step, not
  a build step, and is entirely legitimate. It should simply be STATED PLAINLY in the release notes.

This is DIFFERENT from the `sh` gate. The `sh` gate is about the TARGET artefact needing a native
ARM64 shell at RUNTIME (busybox ash.exe on the user's ARM64 machine) — that is a genuine ARM64
component and is why busybox stays commissioned. `pwd -W` is only about the BUILD-HOST environment
that runs the assembler, which can be any existing MSYS2 (x86-64). Do not conflate them.

CONSEQUENCE: the "run inside MSYS2 clangarm64 shell" line in the B5 task list T4' is over-specified.
CORRECTED T4': run make-file-list.sh MINIMAL_GIT_WITH_BUSYBOX=1 under ANY existing MSYS2 (x86-64 is
fine) with the clang-aarch64 packages installed in its pacman root. No ARM64 runtime required for
assembly. The ARM64-ness lives entirely in the packaged binaries.
