KEY DEFECTS FOUND AND FIXED IN THE PIPELINE TEST (each is a real pipeline
finding, not a property of our binaries):
  * has_pacman_package (make-file-list.sh:166) globs /var/lib/pacman/local/
    $1-[0-9]* — an ABSOLUTE path that ignores --dbpath, AND requires the
    pkgver to start with a DIGIT. Two consequences:
      - must symlink /var/lib/pacman/local -> our root's local db or the check
        misses installed pkgs and re-runs the required install;
      - a stand-in version "UPSTREAM-STANDIN.1" (letter-leading) never matches
        the glob -> forced a pacman -Sy that hit a sync-db checksum error.
        Fixed by versioning the stand-in "1.37.0.upstreamstandin-1".
    IMPLICATION FOR OUR REAL PACKAGES: git and busybox pkgver MUST be
    digit-leading (they are: 2.55.0.x, 1.37.x). No action needed, but noted.
  * pacman -U enforces deps + prompts unless -dd (double nodeps).
  * pactree emits "[unresolvable]" for base deps absent from our snapshot:
    only TWO for the git closure -> cc-libs (compiler-runtime virtual) and
    nano (msys editor). Plus the hardcoded packages-list msys deps
    (msys2-runtime, openssh, filesystem, rebase, git-extra). All satisfied
    here with empty base stubs; in a real MSYS2 host they are present.
  * PACKAGE_VERSIONS_FILE (make-file-list.sh:149-155) runs pacman -Q on the
    whole list and DIES if any is absent. It is OPTIONAL (only release.sh sets
    it). Unsetting it for the file-list step avoids the die; release.sh itself
    would need those packages actually present.
