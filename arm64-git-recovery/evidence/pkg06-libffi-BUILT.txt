BINUTILS/AS FINDING (measured, reportable) — .hidden pseudo-op on aarch64-PE:
  The stale vendor msvc_build/aarch64 fficonfig.h sets HAVE_HIDDEN_VISIBILITY_ATTRIBUTE=1, whose ASM path emits
    FFI_HIDDEN(name) -> `.hidden name`
  GNU as on aarch64-w64-mingw32 REJECTS it: "Error: unknown pseudo-op: `.hidden'". PE/COFF has no ELF-style
  hidden visibility, so .hidden is meaningless on this target. (x86_64-w64-mingw32 historically tolerated/ignored
  some of these; aarch64 as errors hard.) This is a real per-target gap: libffi's config machinery, when it
  believes visibility is available, emits an ELF-only directive that aarch64-PE as cannot accept.
  CORRECT FIX (applied): define FFI_HIDDEN empty for BOTH the C path and the LIBFFI_ASM path on PE. That is what
  a correct ./configure would produce for this target (it would detect .hidden unsupported). Symbols are DLL-
  scoped on PE regardless, so dropping hidden-visibility is semantically fine.
  ALSO: the shipped msvc_build ffi.h/ffitarget.h are for a DIFFERENT libffi version (FFI_BAD_ARGTYPE / ftramp
  member mismatches against 3.4.6 sources) — do NOT use them; generate ffi.h from the in-tree ffi.h.in instead.
